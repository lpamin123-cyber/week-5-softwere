Module Exercise Submission Part A: User Manual Procedure — Creating and Running a Flutter Project Prerequisites Before starting this procedure, ensure you have the following ready on your computer: A computer running Windows, macOS, or Linux. Visual Studio Code (VS Code) installed. Flutter SDK installed and configured in your system PATH. Google Chrome browser installed (used as the web device target). Step-by-Step Procedure Launch VS Code Action: Open Visual Studio Code from your applications menu or desktop shortcut. Expected Result: The main VS Code workspace window opens successfully. Open the Integrated Terminal Action: Click Terminal from the top application menu bar and select New Terminal. Expected Result: A terminal panel appears at the bottom section of the VS Code editor. Generate a New Flutter Project Action: Type flutter create my_first_app in the terminal and press Enter. Expected Result: Flutter creates a new folder named my_first_app containing the starter application template files. Navigate into the Project Folder Action: Type cd my_first_app in the terminal and press Enter. Expected Result: The terminal working directory changes to my_first_app. Run the Application Action: Type flutter run in the terminal, press Enter, and then press key 2 when prompted to choose Google Chrome as the device. Expected Result: Flutter compiles the web project and automatically opens the running application inside a Google Chrome window. Screenshot Description Screenshot Title: Executing flutter run in VS Code and launching the web app. Description: The screenshot shows the VS Code integrated terminal displaying the target device selection list ([1] Windows, [2] Chrome, [3] Edge), alongside an open Google Chrome browser window displaying the default Flutter Counter App (Flutter Demo Home Page). Troubleshooting Note Common Error: No connected devices found. Solution: Ensure your target device is available by running flutter devices in the terminal. If no mobile emulator is open, force Flutter to run on your web browser by typing flutter run -d chrome.

Part B: API Reference Entry — Create Project Task Endpoint HTTP Method & Endpoint: POST /api/v1/projects/{projectId}/tasks Description Creates a new task within a specified project (projectId). This endpoint requires an authenticated user session. Request Body Parameters

Parameter Name Data Type Required Description title String Yes The short name or title of the task. description String Optional Detailed explanation of what the task involves. assigneeId String Optional The user ID of the team member assigned to the task. dueDate String Optional Target completion date formatted as YYYY-MM-DD. priority String Yes Task priority level. Allowed values: low, medium, high.

HTTP Response Codes 201 Created: Task created successfully. 400 Bad Request: Required payload fields are missing or formatted incorrectly (e.g., invalid priority value). 401 Unauthorized: Authentication token is missing, invalid, or expired. 404 Not Found: The specified projectId does not exist in the database. 500 Internal Server Error: Unexpected error occurred on the application server. Example Request Body (JSON)

{ "title": "Design Homepage Wireframes", "description": "Create high-fidelity wireframes for the new product landing page.", "assigneeId": "usr_987654321", "due Date": "2026-10-15", "priority": "high" }

Part C: Brief Technical Report Section — System Architecture Overview Overview This technical report section outlines the high-level architecture for the Project Management API system. The application utilizes a modern RESTful microservices architecture designed for scalability, security, and low latency under peak user loads. Key System Components API Gateway: Serves as the single entry point for client requests, handling rate limiting, request routing, and SSL termination. Authentication Service: Issues and validates JSON Web Tokens (JWT) to secure user sessions and enforce role-based access control (RBAC). Task Management Service: Implements core business logic for project tasks, exposing CRUD endpoints (such as POST /api/v1/projects/{projectId}/tasks). Relational Database (PostgreSQL): Stores persistent application data including project schemas, user profiles, and task assignments with strict foreign key constraints. Recommendations for Production Deployment To ensure high availability, all services should be containerized using Docker and orchestrated via Kubernetes. Continuous Integration/Continuous Deployment (CI/CD) pipelines must run automated unit and integration test suites prior to deploying updates to production environments.
